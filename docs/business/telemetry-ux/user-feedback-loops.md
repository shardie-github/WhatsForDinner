## Action Process

### Bug Reports

**Process**:
1. Receive bug report
2. Reproduce bug
3. Fix bug (if critical, fix immediately; if non-critical, schedule)
4. Test fix
5. Deploy fix
6. Update user (notify fix deployed)

**Priority**:
- **Critical**: Fix within 24 hours (app down, data loss)
- **High**: Fix within 1 week (feature broken)
- **Medium**: Fix within 1 month (minor issues)
- **Low**: Fix when time permits (cosmetic issues)

---

### Feature Requests

**Process**:
1. Receive feature request
2. Evaluate request (user count, impact, feasibility)
3. Add to roadmap (if approved)
4. Prioritize by impact
5. Develop feature
6. Launch feature
7. Update users (notify feature launch)

**Priority**:
- **High**: Many users requesting, high impact
- **Medium**: Some users requesting, medium impact
- **Low**: Few users requesting, low impact
